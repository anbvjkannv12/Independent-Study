# 多視窗實驗結論與後續決策

> 日期：2026-09-28  
> 依據：[`multi_horizon_comparison_results.md`](multi_horizon_comparison_results.md)、預先登記 [`superpowers/specs/2026-09-27-multi-horizon-comparison-design.md`](superpowers/specs/2026-09-27-multi-horizon-comparison-design.md)

## 一、結論

- **實驗有用**：依事先登記的規則，清楚回答了「換預測視窗有沒有幫助」。
- **現在不切換視窗，4h 維持主要視窗**。只有 XRP 1h 通過「比 4h 穩定地強」的判定，1h 目前只算候選假說。
- **現在不訓練深度學習模型**。事先定的門檻是「同一個視窗在至少 2 個幣種通過」，這次沒有達到。

## 二、視窗的意思

四個視窗用的是同一份每小時一列的資料、同一組 53 個特徵，只有標籤不同：

```
target_up = log(close[t+h] / close[t]) > 0
```

也就是「從現在起算，h 小時後的收盤價會不會比現在高」。以 10:00 為例：

| 視窗 | 預測的問題 |
|---|---|
| 1h | 11:00 的價格會比現在高嗎？ |
| 4h | 14:00 的價格會比現在高嗎？ |
| 12h | 22:00 的價格會比現在高嗎？ |
| 24h | 明天 10:00 的價格會比現在高嗎？ |

「4h 模型」是每小時預測一次 4 小時後的方向，不是用 4 小時 K 線。

視窗長短的影響：

1. **標籤重疊**：相鄰兩列的標籤區間重疊 h−1 小時。24h 的 4,000 列 test 只有約 167 段互不重疊的區間，有效樣本少、信賴區間寬，所以實驗使用 block bootstrap 和 24 列 purge。
2. **訊號性質**：短視窗較容易捕捉短期反轉；長視窗受新聞、總體事件影響較大，技術特徵較難預測。
3. **交易意義**：1h 代表每小時換倉，交易頻繁、成本高；AUC 高不代表扣成本後較好。

## 三、結果重點

1. **視窗越短，訊號越清楚**：1h 四個幣種都通過訊號關卡；4h 只有 BTC、ETH 通過；12h 和 24h 只有 ETH 通過。SOL、XRP 在 12h、24h 的 AUC 約 0.50。
2. **1h 在四個幣種方向一致，但只有 XRP 過線**：四個幣種 1h 比 4h 都高約 +0.015。BTC、ETH 三個 fold 都是正值且大於 ε，只差在 Holm p（0.075、0.085）；SOL 的 fold 1 是負值。
3. **1h 的提升主要來自短期反轉**：persistence 在 1h 的 AUC 約 0.46～0.48，低於 0.5，反向使用約 0.52～0.53。XGB 相對反向 persistence 只多出約 0.01～0.02，而且 1h 交易次數是 4h 的 4 倍，成本很可能吃掉優勢。
4. **XGBoost ≈ Logistic**：多數組合的差距在 ±0.01 以內。訊號大多是簡單、接近線性的關係，這是不建議現在做深度學習的主要理由。
5. **其他**：多數組合 test AUC 低於 validation AUC，訊號隨時間衰退；校準後 Brier 只比常數基準好約 0.001，只剩排序能力。

## 四、各視窗的決策

| 視窗 | 決策 | 原因 |
|---|---|---|
| 12h、24h | 放棄 | 沒有任何幣種比 4h 好；SOL、XRP 幾乎沒有訊號 |
| 1h | 保留為候選，不切換 | 只有 XRP 正式通過；test 時段先前用過，不算獨立確認；交易成本高 |
| 4h | 維持主要視窗 | 沒有證據顯示其他視窗穩定比它好 |

不因 BTC、ETH「差一點」就事後放寬標準。

## 五、切換到 1h 的條件（滿足其一）

- **新資料驗證**：2026-08-09 之後的新資料累積到約 4,000 列 1h（大約 2027 年 1 月下旬），在沒碰過的資料上用寫死的規則驗證，1h 仍穩定比 4h 強，且至少 2 個幣種通過。
- **成本回測**：扣掉交易成本後，1h 表現仍比 4h 好。

## 六、下一步

3. 報告補充：「XGB−persistence」差值會高估 XGB 的優勢，應補上對反向 persistence 的比較，或註明 persistence AUC < 0.5 代表短期反轉。
