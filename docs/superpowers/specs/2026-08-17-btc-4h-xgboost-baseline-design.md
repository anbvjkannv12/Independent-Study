# BTC 4 小時 XGBoost Baseline 設計

## 目的

建立第一套可重現的 BTCUSDT 4 小時漲跌分類基準流程。此流程提供後續 LSTM、Transformer 與其他模型公平比較的共同資料切分、特徵契約與評估標準。

## 範圍

- 輸入資料固定為 `data/features/btc_4h.csv`。
- 使用 `logs/feature_manifest.json` 內定義的 53 個 `feature_names`。
- 分類標籤固定為 `target_up`；`future_log_return` 僅供資料稽核，不可作為特徵。
- `open_time` 僅供排序與切分；`is_imputed` 僅供資料品質追蹤。兩者均不可作為模型特徵。
- 本版本不包含超參數搜尋、交易策略回測、LSTM 或 Transformer。

## 資料流程與切分

1. 載入 CSV，解析 `open_time` 為 UTC 時間並依其嚴格遞增排序。
2. 驗證 53 個特徵與 `target_up` 存在，且特徵與標籤均無遺漏值。
3. 依列數、時間先後切分為 70% 訓練集、15% 驗證集、15% 測試集；資料不可隨機洗牌。
4. 只在訓練集擬合 XGBoost；以驗證集評估固定設定；測試集僅在流程完成後產生一次最終報告。

不會對資料重新取樣，也不會把未來資料用於訓練或模型選擇。若任何分割集標籤只含單一類別，流程必須停止並說明原因。

## 模型與比較

主要模型為固定亂數種子的 `XGBClassifier`。模型使用二元分類機率輸出，預設以 0.5 作為類別判定門檻。

同一個驗證集與測試集上，另計算兩個不使用特徵的對照組：

- 全部預測上漲（`target_up = 1`）。
- 全部預測訓練集中較多的類別。

對照組用來判斷模型是否僅利用資料不平衡取得表面 Accuracy。

## 結果與介面

訓練程式由命令列執行，接受資料、manifest 與輸出目錄路徑。成功時輸出 JSON 摘要，至少包含：

- 訓練、驗證、測試的筆數與 UTC 起訖時間。
- 53 個實際使用的特徵名稱。
- 模型固定設定與亂數種子。
- 模型和兩個對照組各自在驗證集、測試集的 Accuracy、Precision、Recall、F1、ROC-AUC 與混淆矩陣。
- XGBoost 依 gain 排序的特徵重要度。

另外建立可重現的 notebook，讀取既有 JSON 結果並呈現資料切分與評估表，不重新實作訓練邏輯。

## 可靠性與測試

單元測試覆蓋：特徵契約載入、嚴格時間排序、無重疊時間切分、禁止目標與稽核欄位進入特徵矩陣、對照組指標，以及上述輸入驗證失敗情況。

訓練程式任何輸入契約違反都以非零結束碼失敗，且不寫出不完整的正式結果檔。測試資料以小型合成時間序列建立，不依賴五年 CSV 才能執行。

## 驗收條件

- 能從專案根目錄以單一命令重跑 BTC 4 小時分類 baseline。
- 測試、模型與兩種對照組都使用完全相同的時間切分。
- 最終 JSON 可追溯資料、特徵、切分與所有評估結果。
- 新增測試全部通過，既有測試亦維持通過。
